## Round 4: context mode removed, triage added
Rounds 1-3 above that describe `scan.py context` (M1 and its follow-ups) describe code that no longer exists. `tree`, `history`, the rules and the git flags are unchanged (only two comment lines in the rule tables were reworded).
- Why `context` was deleted: it tried to print file text with the secrets masked, and the masking leaked in three consecutive reviews: round 2 printed values in five shapes (YAML `PASSWORD: x`, `redis://:pw@`, a quoted value under 12 characters, `-e APP_SECRET=x`); round 3 printed them in 13 of 21 shapes (`Authorization: Bearer x`, `SecretStr("x")`, `setenv(...)`, `--password x`, `.netrc`, block scalars...); the round-3 default-deny rewrite still printed 12 of 13 new shapes (`- name: DB_PASSWORD` / `value: x`, CSV and markdown rows under a password header, `redis-cli -a x`, `docker login -p x`, SQL `N'x'`/`E'x'`, `accesskey=x`). Masking text you intend to print is a blacklist problem: every new shape needs a new pattern, and a miss prints the secret.
- Deleted: the `context` mode, its lexer (`lex`, `find_close`, `apostrophe_in_word`), the line renderer (`render_file`, `render`, `whole`, `keyword_value`, `file_mode`), the masking regexes and tables (`KEYWORD_CTX`, `ARG_RES`, `USERINFO`, `QUOTES`, `PEM_*`, `ENV_LINE`, `CODE_EXT`, ...), and the `context` CLI branch. No code path now prints a line, or part of a line, from a file.
- Added: `scan.py triage OUTFILE`. It reads the scan's own report, re-reads each finding's line in memory, and prints ONE tab-separated line of fixed fields per finding (`src rule loc commit remote cat name len ref placeholder pw_eq_user host in_example verdict`). Nothing is ever masked because nothing is ever printed: every field is a number, yes/no, a fixed word, or one of two guarded copies out of the blob. `name_of` copies an identifier-shaped name (`[A-Za-z_][A-Za-z0-9_.-]{0,63}`) that is tied directly to the value (inside the rule's own match, or right before `=`/`:` and the value; list neighbours are never candidates, and an identifier that is itself the value of an earlier `=`/`:` (`a=b=SECRET`) is dropped); `host_form` copies a host only if loopback, reserved (`*.test` `*.example` `*.invalid` `*.localhost` `*.internal`, example.com/net/org) or a single label, else `remote:<registrable domain>` or `remote:ip`. Both pass through `safe()`: a string that matches any vendor-key rule or looks random (12+ letters-and-digits) is not printed.
- Facts: `remote` from `git branch -r --contains <sha>` (yes/no, unknown when there are no remote-tracking branches or the sha is bad); `cat` by path only; `len`, `ref`, `placeholder`, `pw_eq_user` computed in memory and printed as a number or yes/no; `in_example` compares the scan's own fingerprints inside the report (so the report must come from one `all` run); `verdict` is `likely-placeholder` only for (URL hit: loopback/reserved/single-label host plus placeholder, user = password, example file or same value in an example file) or (other hit: `placeholder=yes` in a test/ci/docs/example path), else `unclassified`, which goes to the founder.
- Safety properties: one `print` in the triage code and its fields are fixed; `rule`, `commit`, `src` and the line number are validated before use; `loc` is the path from the report with control characters and non-ASCII escaped; any exception prints only `scan.py: triage failed` (an exception message could quote file text); blobs are read with `git cat-file blob` only, never from the working tree.
- Size: the triage section is 82 non-blank lines: the printer, `triage()`, is 27 of them and the tables and helpers are 55 (the target of 60 is met by the printer, not by the whole section; the three functions that copy bytes out of a blob, `safe`, `name_of` and `host_form`, are 19 lines together). A shorter version would have to drop one of the requested facts.
- Not asked for, closing the same class: a `safe()` guard on printed names and hosts; `remote:ip` for non-loopback IP hosts; three-label registrable domains for `co.uk`/`com.au`-style names; `name: type = value` yields the name (`resend_api_key`, not `str`); the end-anchored name rule excludes comma-separated neighbours on purpose, so `setenv("NAME", "x")` shows `name=NAME` only through the rule's own match.
- SKILL.md: step 3 is now `scan.py triage` (fields, verdict rules, limits); `git show`/`cat`/Read of a hit is forbidden outright; `unclassified` hits go to the founder to check in their own terminal; the agent never opens the line; limits updated (triage only sees what the sweep flagged, so shapes the regexes miss are not visible to it); cleanup also deletes `$LOG/triage.txt`.
- Self-test (throwaway repos, fake values, never AVP; `harness4.py`): 44 rows, 0 failing. Every shape from every round (88 single-line + 20 multi-line fixtures + 20 more: the 7 named in the round-4 message, plus traps for the two byte-copying fields: a secret-looking name before a key, a secret-looking host, a list neighbour, a comma-adjacent value, chained assignments (`x=v=KEY`, `x: v: KEY`), a quoted value containing `=` and `:`, two assignments on a line, user=password URLs, IPv4 and IPv6 hosts, a file name with spaces and quotes) was run through triage as a fabricated tree and history record for EVERY rule: 21,560 findings, 21,560 output lines, every line matches the field grammar, zero bytes of any value in any non-`loc` field. A real `all` scan of the same repo triaged cleanly (130 findings, 130 lines). Representative hits (placeholder in `.env.example`, `postgres:postgres@localhost` in a test, a CI password, a typed default in `config.py`, a Supabase URL only in history on a pushed commit) classify as expected; no remote-tracking refs gives `remote=unknown`. Tree, history, rules and hostile-git-config rows pass unchanged (root commit, `-diff` file, merged hunk, `diff.relative` from a subdirectory, quoted path, stash excluded).
- Negative controls (mutated copies of `scan.py` in the scratch dir; the real file was never edited): printing the value when there is no name fails 4 rows (grammar, zero-bytes, secret-looking name, real-scan); removing `safe()` fails 4 (zero-bytes, name guard, host guard, real-scan); returning the raw host fails 5 (zero-bytes, host guard, real-scan, demo output, remote-URL verdict); forcing `verdict=likely-placeholder` fails 3 (docs, src, remote-URL verdict); removing the chained-assignment check fails 2 (zero-bytes, real-scan). All five mutants were detected.

## Round 5
Supersedes round 4's description of the `name` rule, host forms, placeholder list and verdict policy. `tree`, `history` and the rules are byte-identical to round 4 (checked).
- Fix 1, `name` printed part of a value (`API_KEYS='["k1","k2"]'`, `process.env.X_TOKENS = "['k1','k2']"` gave `k1`): the old rule searched the whole match for the first quoted identifier. Every other keyword rule: the leading identifier of the match (the key). Value-shaped rules (Stripe, URL, ...): the identifier directly before the first `=` or `:` that is outside any quoted string in the text left of the match (`://` skipped), so a JSON key or list item inside a quoted value is never a candidate. The identifier must end at a non-identifier character, so a 64-character prefix of a longer run is never printed.
